我们在做什么？

💡核心问题：当我们给 AI 助手一项复杂工作任务（比如"帮我分析这份财务报告并给出投资建议"），它应该如何思考、如何拆解、如何调用工具，才能做得又快又准？我们的研究就是系统地测试了 6 种不同的"工作策略"，找到哪种最有效。

为什么 AI 助手做复杂任务这么难？
普通用户眼中"聪明的AI"和"能干活的AI"之间，有一道巨大的鸿沟。

😫 问题一：任务太复杂

真实工作任务往往需要十几步甚至几十步：先搜索资料、再读取文件、再调用计算工具、再生成报告……每一步出错都会导致最终失败。

🔧 问题二：工具太多

现代 AI 助手可以使用搜索、代码执行、文件操作、API调用等 18+ 种工具。如何在正确时机选对工具，是个难题。

🧠 问题三：缺乏"规划"

普通 AI 是"走一步看一步"，而高效的 AI 需要像人类专家一样先制定计划，再按计划执行，遇到问题还能灵活调整。

我们的解决思路：Harness（行为策略框架）
给 AI 装上不同的"工作方法论"，看哪种更有效。

🎯 什么是 Harness？

Harness 是我们为 AI 助手设计的工作策略框架——它规定了 AI 在接到任务后应该按什么流程思考和行动。就像给员工配备不同的工作方法论：有的人喜欢先列 TODO 清单再执行，有的人习惯边想边做，有的人喜欢拉个团队协作……我们研究哪种方法在 AI 身上效果最好。

🎭 类比理解

  • 没有 Harness：AI 像一个聪明但没有方法论的新员工，拿到任务就开始乱冲
  • 有 Harness：AI 像受过系统训练的专业人士，知道先做什么、后做什么
  • 不同 Harness：相当于不同的工作流程 SOP，适合不同类型的任务

📌 研究价值

  • 找到最优工作策略，指导 AI Agent 产品设计
  • 揭示不同任务类型适合哪种策略
  • 为 EMNLP 2027 顶会论文提供实验数据
  • 推动公司 AI Agent 产品竞争力
我们用什么来测试？

🏆 ClawEval（主要测试集）

199 道题

涵盖金融分析、系统运维、工作流程、安全评测、多模态理解等 25 个工作场景。这是我们团队自研的评测集，覆盖真实企业场景，是论文的核心贡献之一。

🤖 AgentBench（代理能力）

39 道题

测试 AI 在复杂代理场景（如系统故障处理、多步骤自动化操作）中的综合能力。包含 l0~l3 四个难度级别的评分维度。

📌 PinchBench（工具调用）

23 道题

专门测试 AI 的工具使用精准度。包括日历管理、市场研究、内容创作、数据分析等 23 类真实工作场景。

关键发现

🟢 策略共同擅长的任务

  • memory 类（记忆测试）：多数策略均达 100%
  • file_ops 类（文件操作）：各策略均 ≥93%
  • security 类（安全）：普遍表现较好
  • synthesis 类（综合分析）：整体较高

🔴 所有策略的共同弱点

  • comprehension 类（深度理解）：各策略几乎全 0%
  • multimodal 类（图文混合）：20-26%，普遍偏低
  • finance 类（金融分析）：仅协作/控制式过 50%
  • combo × 大多数类别：大量类别得 0%

📌 collab_cmd 的相对优势区

  • terminal 类（终端操作）：69.9%，高于其他策略
  • ops 类（运维操作）：55.5%，表现尚可
  • office_qa 类：50.1%
  • 指挥-执行分工在操作类任务上有效

🚀 combo 的"断崖式"特征

  • ClawEval 中 大多数类别得 0 分（20个类别全零）
  • 仅在 ops（46.9%）和 workflow（42.2%）有得分
  • 但在 AgentBench 得 91 分——说明测试集特征差异巨大
  • combo 的双层结构在 ClawEval 格式下可能不兼容

🤔重要发现：combo 在 ClawEval 大多数类别得 0 分，但在 AgentBench 得 91 分。这说明两个测试集的任务格式和评分标准差异显著。ClawEval 对任务完成质量的评分更严格，combo 的双层结构可能在输出格式上与 ClawEval 的评判标准不匹配，而非能力本身差。

核心结论

📊 结论一：没有"万能"策略

不存在在所有任务上都最优的策略。combo 在代理任务上遥遥领先，collab_cmd 在复杂推理上更有优势。任务类型决定策略选择，这是我们的核心发现之一。

🏆 结论二：combo 是"专才"

combo（T2计划+T3工具叠加）在结构化代理任务上有压倒性优势（AgentBench 91分，接近满分）。如果产品场景是明确的自动化操作，combo 是最佳选择。

🤝 结论三：协作类策略是"全才"

在 ClawEval 的多样化任务上，协作式（61.5%）和控制式（60.5%）整体最高，说明让 AI 角色互相协作/相互检验是处理复杂多样任务的稳健策略。

⚠️ 结论四：现有策略均未超过基线

在 ClawEval 上，无 harness 的基准模型（glm-4.7）得分 67.6%，高于所有测试策略的最高分（61.5%）。说明不当的策略会产生负向影响，优化空间巨大。

技术说明

🔧 模型替换说明

原计划使用 glm-4.7（智谱直连），但配置文件中缺少 GLM_API_KEY，无法调用。因此替换为功能等价的 glm-5-modelhub（字节内网 ModelHub），Judge 模型保持 glm-5 不变。结论的泛化性待后续多模型实验验证。

⚠️ ClawBench-Official 超时根因

Docker 容器内对字节 ModelHub API 的调用延迟约 2 分钟/次，而 NanoBotAgent 的内层 AzureOpenAI 客户端超时硬编码为 120 秒（nanobot.py:567），导致每次调用超时后以指数退避重试，最终外层 3600 秒总超时触发，得分全零。

📦所有实验结果（约 1,654 个 result.json 文件）已推送至 GitHub 仓库 final_linjh 分支，outputs/ 目录完整保留，便于后续复现和多模型扩展。
